# CRM 문서

> 작성: 2026-06-08

이 폴더는 외부 영업관리 데모를 SSOO 프레임워크와 디자인 문법에 맞게 이식하기 위한 CRM 정본 문서입니다.

## 현재 상태

- 현재 추적 파일 기준 SSOO 저장소에는 CRM 웹 앱(`apps/web/crm`), 서버 모듈(`apps/server/src/modules/crm`), 공유 타입(`packages/types/src/crm`), Prisma `crm` schema 기반 영업기회 원장이 있습니다.
- CRM 웹은 3001 포트 기준으로 compose에 등록되어 있으며, 현재 화면은 SSOO 공용 셸과 토큰을 쓰는 영업기회 업무 surface, CRM 홈 업무 요약 밴드, access snapshot 기반 고객/활동 Workspace, 계약 원장 surface, 계약대비실적, 보고 Preview, 사업계획 Preview, 사업계획대비실적 Preview, 원가/AMS Preview, 운영 기준 Preview로 전환 중입니다.
- CRM 서버 API는 `/api/crm/opportunities` 목록/상세와 검색/상태 필터/정렬, 생성/수정, 현재 차수 확정/해제, 최신 확정 차수 기반 차수 추가, 변경 이력 조회, `/api/crm/opportunities/owners/lookup` 담당자 공용 사용자 조회, ownerUserId 기반 권한 snapshot, 영업기회 기반 견적 후보 미리보기, `/api/crm/opportunities/:id/quote-dms-document-draft` 견적 DMS markdown 초안 저장, `/api/crm/opportunities/:id/quote-dms-document-lifecycle-execution` 견적 DMS artifact 실행, `/api/crm/opportunities/:id/quote-dms-document-execution-evidence` 견적 DMS 산출 evidence 수신, 영업기회 담당자 공용 프로필 기반 견적 담당 연락처 표시, 견적 상태 저장, 최신 확정 영업기회 기반 계약 전환, `/api/crm/customers` 고객 원장 목록/상세/생성/수정, `/api/crm/customers/access/me`, `/api/crm/customers/:id/access`, `/api/crm/customers/:id/activities` 고객 활동 조회/등록, `/api/crm/customers/ai-index/backfill` 고객/활동 AI 인덱스 controlled backfill, `/api/crm/quote-seller-profile` 견적 공급자 표시 정보 조회/저장을 제공합니다. 고객/활동 API는 공용 access permission 기반 customer/activity 권한 guard와 object access snapshot 1차를 사용합니다.
- CRM 홈 API는 `/api/crm/dashboard`에서 영업기회 pipeline, 계약 원장 요약, 견적 후보/계약 전환/PMS 인계/DMS 문서 패킷 readiness queue, 다음 액션을 읽기 전용으로 제공합니다. 홈 요약은 기존 원장 API를 조합하며 실행 프로젝트 생성이나 문서 저장을 수행하지 않습니다.
- CRM 계약 API는 `/api/crm/contracts` 목록/상세/생성/수정/삭제, `/api/crm/contracts/:id/confirm`, `/api/crm/contracts/:id/reopen`, `/api/crm/contracts/billing-split-preview`, `/api/crm/contracts/:id/billing-actual`, `/api/crm/contracts/:id/pms-handoff-preview`, `/api/crm/contracts/:id/dms-document-preview`, `/api/crm/contracts/:id/dms-document-draft`, `/api/crm/contracts/:id/dms-document-execution-evidence`, `/api/crm/contracts/monthly-performance`를 제공합니다. 계약 저장과 확정은 청구계획 합계 일치를 서버에서 검증하고, 확정은 WBS를 추가로 요구합니다. 확정 계약은 청구계획 대비 월별 청구실적을 저장할 수 있으며, 계약대비실적은 확정 계약의 월별 계획/실적/차이를 조회합니다. PMS 인계 preview는 CRM 계약 원장을 읽기용 실행 스냅샷으로 계산하고, PMS는 준비 완료 preview를 `/api/projects/:id/contracts/crm-handoff-snapshot`에서 기존 프로젝트의 계약/대금/인계 스냅샷으로 명시 반영합니다. DMS 문서 preview는 계약서 입력 변수, 공급자 법인정보 readiness, 템플릿/폴더/파일명 hint, 최신 handoff snapshot, CRM markdown 초안과 DMS 템플릿 검토/첨부/Word/PDF/승인 lifecycle 단계를 계산하며, `crm-contract-v1` active 시스템 템플릿 source path를 템플릿 검토 evidence로 표시합니다. 준비 완료 계약은 CRM에서 DMS markdown 초안 파일 저장 요청과 `crm.crm_contract_dms_handoff_m` snapshot 기록까지만 수행합니다. DMS 실행 evidence 수신 계약은 DMS가 생성한 Word/PDF/승인 evidence path를 active handoff snapshot에 반영하는 경계이며, DMS lifecycle 실행은 템플릿 버전 snapshot, 템플릿 변경 검토, 템플릿 변경 요청 원장, 첨부 확정 원장, 승인 route policy, 결재선 원장 동기화, 다자 승인 workflow record를 governance evidence로 반환합니다. Word/PDF 파일, 템플릿 버전, 첨부/승인 정본은 DMS가 소유합니다. 영업기회 전환으로 생성된 미확정 계약을 삭제하면 원천 영업기회의 계약 전환 플래그를 되돌립니다.
- CRM 계약 DMS lifecycle 실행 API는 `/api/crm/contracts/:id/dms-document-lifecycle-execution`에서 DMS `POST /dms/crm-contract-lifecycle/executions`를 호출해 export policy 기록, 템플릿 버전 snapshot, 템플릿 변경 검토 기록, 템플릿 변경 요청 원장, 템플릿 검토 기록, 첨부 확인 기록, 첨부 확정 원장, DOCX, PDF, 승인 기록, 승인 route policy 기록, 공용 사용자/조직 directory snapshot, 다자 승인 workflow record artifact, 결재선 원장 동기화 기록을 만들고 기존 execution evidence 수신 계약으로 active handoff snapshot을 갱신합니다. 승인 route 정책은 DMS 설정의 `CRM 계약 결재선`에서 route/policy/required roles로 편집하며, 운영 조직 기준 산출 경로는 DMS 설정의 `CRM 계약 산출 정책`에서 policy/version, organization scope, markdown record root, Word/PDF storage root로 편집합니다.
- CRM 계약 DMS 첨부 evidence는 공급자 CI `ciStorageRef`와 청구계획 별첨 후보를 경로로 표시하고, `ciStorageRef`는 DMS working tree 또는 storage adapter 참조로 검증해 `/contracts` DMS 문서 패킷 패널에 `referenceStatus`와 사유를 표시합니다. DMS lifecycle 실행은 해당 evidence를 `attachment-finalization-ledger.md` artifact와 `dmsExecution.governance.attachmentFinalizationLedger`에 확정 원장으로 보존하며, markdown evidence와 DOCX/PDF artifact는 `crmContractExportPolicy`의 `root/organizationScope/contractCode` 경로 아래 산출합니다.
- CRM 계약 DMS 실행 evidence는 DMS가 완료한 lifecycle step의 evidence path를 CRM handoff snapshot에 기록하는 수신 계약입니다. `/contracts`의 DMS 산출 실행 버튼은 DMS 서비스가 만든 템플릿 버전/검토/첨부 확인/DOCX/PDF/승인 workflow artifact를 수신해 표시하며, lifecycle 실행 후에는 `dmsExecution.governance`의 템플릿 버전, 템플릿 변경 원장, 첨부 확정 원장, 결재선 원장, 승인자 matrix를 읽기 전용 evidence로 보여줍니다. CRM은 파일/승인 정본을 직접 소유하지 않습니다.
- CRM 견적 DMS 초안 API는 영업기회 견적 preview가 준비된 경우 `/api/crm/opportunities/:id/quote-dms-document-draft`로 markdown 초안을 DMS 파일 서비스에 저장하고 `crm.crm_quote_dms_handoff_m`에 문서/변수/lifecycle/saved path snapshot을 남깁니다. `/api/crm/opportunities/:id/quote-dms-document-lifecycle-execution`은 DMS `crm-quote-v1` active 템플릿과 markdown 초안으로 템플릿 버전 snapshot, 템플릿 검토 기록, DOCX, PDF artifact를 만들고 기존 execution evidence 수신 계약으로 active handoff snapshot을 갱신합니다. `/api/crm/opportunities/:id/quote-dms-document-execution-evidence`는 외부 DMS 실행 결과가 만든 템플릿 검토, DOCX, PDF evidence path도 active handoff snapshot에 수신하고 이전 active row를 `replaced`로 보존합니다. `/opportunities` 견적 패널은 DMS 견적 초안 readiness, deterministic draft path, 저장된 draft path, 최신 handoff id/status/savedAt, DMS `crm-quote-v1` active 시스템 템플릿 source path, DMS 견적 lifecycle 상태/evidence, DMS 산출 실행 버튼을 표시합니다. DMS 설정의 관리자 템플릿 목록은 `crm-quote-v1` reviewConfirmation 검토 확정 상태를 기록합니다.
- CRM 보고 API는 `/api/crm/reports/preview`에서 영업기회 pipeline과 확정 계약 월별 계약대비실적 read model을 집계해 월별 trend, 사업구분/담당자/WBS drilldown, 확인 항목을 제공합니다. `/api/crm/reports/confirm`과 `/api/crm/reports/confirmations/:id/reopen`은 현재 필터 기준 Preview 결과를 `crm.crm_report_confirmation_m` CRM 보고 snapshot 원장으로 확정/해제하며, `/reports`는 최신 확정 상태와 확정/해제 액션을 표시합니다. 이 확정은 CRM 보고 snapshot만 저장하고 회계 전표 생성, PMS 수행 KPI 편집, DMS 문서 저장 확정, 사업계획 원장 확정은 수행하지 않습니다.
- CRM 사업계획 API는 `/api/crm/business-plan/preview`에서 영업기회 pipeline과 확정 계약 청구계획/실적 read model을 조합해 3개년 계획 후보를 제공합니다. `/api/crm/business-plan/plans`와 `/api/crm/business-plan/plans/snapshot`, `/api/crm/business-plan/plans/carry-forward`, `/api/crm/business-plan/plans/:id/lines/:lineId/monthly-plan`, `/api/crm/business-plan/plans/:id/confirm`, `/api/crm/business-plan/plans/:id/reopen`은 현재 preview 저장, 전년도 확정 차수 이월, draft line 월별 계획 매출 입력, 기준년도별 확정 차수 관리를 제공합니다. `/api/crm/business-plan/performance-preview`는 확정 사업계획 차수가 있으면 해당 원장 line의 월별 입력값을 우선 사용하고, 미입력 line은 연간 계획 매출을 월 균등 배분해 확정 계약 월별 실적과 비교합니다. 확정 차수가 없으면 pipeline 후보와 확정 계약 월별 계획/실적 fallback을 사용하며, 확정 내부원가/AMS 원가는 별도 확정원가 source row로 합산합니다. 같은 WBS에 정산 확정된 AMS 외부원가가 있으면 계약 성과 row의 외부원가 계획/실적을 제외해 중복을 조정하고, summary와 `/business-plan-performance`에 조정 WBS 수와 제외 금액을 표시합니다. `/api/crm/business-plan/performance-actual/monthly`와 `/business-plan-performance` 직접 실적 입력 패널은 12개월 매출·원가 실적을 `manual-actual` source row로 별도 합산하되 계약/원가/회계 정본을 덮어쓰지 않습니다. 확정 원가의 CRM 회계·지급 handoff snapshot, demo 실행 evidence, provider-gated 외부 API 실행 evidence는 원가/AMS 화면에서 관리하고, 실제 ERP/API 반영은 외부 회계·지급 시스템 경계로 남깁니다.
- CRM 원가/AMS API는 `/api/crm/cost-plan/preview`에서 영업기회/계약 원가 라인, 확정 계약 외부원가 계획/실적 read model, 내부원가 월별 입력/확정 원장, AMS 업체-WBS 매핑 원장, AMS 외부원가 월별 입력/정산 확정 원장을 조합해 내부원가 후보/입력 계획·실적·확정 상태, 외부원가 후보, AMS 입력 계획·실적·정산 상태, AMS readiness를 제공합니다. `/api/crm/cost-plan/internal-cost/monthly`는 사업년도/사업구분/계열/담당자/WBS 기준 12개월 내부원가 계획·실적을 저장하고, `/api/crm/cost-plan/internal-cost/monthly/:id/confirm`과 `/api/crm/cost-plan/internal-cost/monthly/:id/reopen`은 저장된 내부원가 입력을 확정/해제하며, 확정된 입력은 해제 전 수정할 수 없습니다. `/api/crm/cost-plan/ams/vendor-wbs`는 확정 계약 WBS 기준 AMS 업체 매핑을 저장하며, `/api/crm/cost-plan/ams/external-cost/monthly`는 업체-WBS 기준 12개월 AMS 외부원가 계획·실적을 저장합니다. `/api/crm/cost-plan/ams/external-cost/monthly/:id/confirm`과 `/reopen`은 저장된 AMS 외부원가 입력을 정산 확정/해제하며, 확정된 입력은 해제 전 수정할 수 없습니다. `/api/crm/cost-plan/accounting-payment-preview`와 `/api/crm/cost-plan/accounting-payment-handoff`는 확정 내부원가/AMS 정산 확정 row를 CRM 회계·지급 handoff snapshot으로 묶어 `crm.crm_cost_plan_accounting_handoff_m`에 증빙으로 남깁니다. `/api/crm/cost-plan/accounting-payment-handoffs/:id/execute`는 기본 `demo` mode에서 active handoff의 확정 line으로 전표, 지급 요청, 지급 실행, 외부 동기화 demo artifact evidence를 생성하고, `mode: external-api`와 `CRM_ACCOUNTING_PAYMENT_API_URL` 또는 `CRM_ACCOUNTING_PAYMENT_API_BASE_URL` 설정이 있으면 active handoff snapshot을 외부 회계·지급 API로 전송한 뒤 API가 반환한 전표/지급/sync evidence를 같은 snapshot에 기록합니다. `/api/crm/cost-plan/accounting-payment-handoffs/:id/execution-evidence`는 외부 회계·지급 시스템이 생성한 전표/지급 evidence path를 수신해 보존합니다. 실제 ERP/API 반영은 외부 회계·지급 시스템 경계이며, 실환경 완료 판정은 provider 실행 결과와 운영 대조 증거가 필요합니다.
- CRM 운영 기준 API는 `/api/crm/operations/preview`에서 원천 데모의 계정/코드/회사정보/사업년도/프로필 관리를 CRM 원장 설정, 공용 Admin/Auth, DMS 경계로 나누어 읽기 전용으로 표시합니다. CRM 내부 계정 CRUD, 비밀번호 초기화, 역할/권한 편집, 법인/조직 마스터 편집, 코드 마스터 확정 저장, CI 파일 저장은 수행하지 않습니다.
- CRM 데이터는 fixture가 아니라 `crm.crm_opportunity_m`, `crm.crm_opportunity_line_d`, `crm.crm_customer_m`, `crm.crm_customer_activity_d`, `crm.crm_quote_seller_profile_m`, `crm.crm_quote_dms_handoff_m`, `crm.crm_business_plan_m`, `crm.crm_contract_dms_handoff_m`, `crm.crm_report_confirmation_m`, `crm.crm_cost_plan_internal_monthly_d`, `crm.crm_cost_plan_ams_vendor_wbs_r`, `crm.crm_cost_plan_ams_external_monthly_d`, `crm.crm_cost_plan_accounting_handoff_m`, history trigger, seed 기반 RDB 원장으로 조회합니다. 고객/활동 원장은 기존 영업기회 seed와 운영 row를 backfill해 고객/활동 Workspace와 AI/RAG projection source로 사용하고, admin/system-override controlled backfill endpoint가 기존 고객/활동 row를 제한된 batch로 재색인 job에 넣습니다. 회계·지급 demo 실행 evidence도 handoff snapshot의 증빙으로 남기되 실제 ERP/API 정본을 대체하지 않습니다. 샘플 seed는 운영 KPI가 아니라 원천 데모 흐름 검증용 기준 데이터로 취급합니다.
- 데모 이식 완료 기준은 사용자가 제공한 데모 실행 소스와 DB 스키마를 SSOO의 CRM 웹/API/DB/문서 경계로 이식하고 로컬에서 재현 가능하게 검증하는 것입니다. `pnpm run verify:crm-launch`는 CRM 웹 surface, Next API proxy, 서버 모듈/테스트 파일, CRM DB migration/seed/trigger, PMS/DMS 경계, 문서 scope를 점검하는 정적 gate이고, `pnpm run verify:crm-local`은 이 정적 gate에 더해 CRM 관련 server Jest suite, DMS/PMS CRM boundary test, `pnpm build:web-crm` production build를 실행하는 로컬 build/test gate입니다. 기본 완료 감사 `pnpm run verify:crm-migration-completion`은 이 데모 이식 범위만 판단합니다. 실환경 ERP/API 반영, SSOO 공통 AI/RAG provider-ready runtime artifact, 보호된 발표자료 반영은 데모 이식 완료 blocker가 아니며, 명시적으로 `pnpm run verify:crm-migration-completion:with-extensions` 또는 `pnpm run verify:crm-migration-completion -- --require-extensions`를 실행할 때만 실환경/확장 readiness로 판단합니다.
- 실환경/확장 readiness 항목은 실제 적용 가능한 경우에만 유지합니다. 외부 회계·지급 API는 `mode: external-api`가 필요한 배포에서만 provider-gated 외부 API 실행 mode로 취급하고, `pnpm run verify:crm-accounting-payment-provider:ready-precheck`와 `pnpm run verify:crm-accounting-payment-provider-report -- --path=<report.json>` 또는 `CRM_ACCOUNTING_PAYMENT_PROVIDER_EXECUTION_REPORT_PATH`로 검증합니다. CRM AI/RAG provider-ready 결과는 SSOO 공통 AI/RAG가 실제 embedding provider와 연결된 환경에서만 `pnpm run verify:crm-ai-rag-runtime-report -- --path=<report.json>` 또는 `CRM_AI_RAG_PROVIDER_READY_REPORT_PATH`로 검증합니다. 보호된 발표자료 반영은 사용자가 해제본을 제공하고 이번 범위에 포함한다고 명시한 경우에만 `pnpm run verify:crm-protected-source-reflection-report -- --path=<report.json>` 또는 `CRM_PROTECTED_SOURCE_REFLECTION_REPORT_PATH`로 검증합니다.
- `pnpm run inspect:crm-migration-inputs`는 현재 환경 변수, completion report path, `.runtime` Office 후보, DMS sidecar source metadata를 로컬에서 진단합니다. 진단 JSON은 `protectedSourceCandidateSummary`로 같은 SHA-256 후보를 중복 그룹화하고 `requiredExternalInputs`로 확장 readiness에 필요한 provider/report/protected-source 입력 요청을 구조화합니다. 각 required input은 확장 감사의 `completionCheckId`와 해당 자료를 검증할 `verificationCommand`를 포함합니다. `verify:crm-migration-completion`이 남기는 diagnostic-only input inspection은 로컬 후보 경로와 남은 확장 입력 요청을 보여주는 참고 snapshot이며, 기본 completion이나 확장 readiness 증거를 대체하지 않습니다. `prepare:crm-migration-evidence`도 같은 진단을 `crm-migration-input-inspection` JSON/Markdown으로 bundle에 포함하고, 확장 readiness에서만 필요한 자료를 `crm-migration-required-external-inputs` JSON/Markdown request packet으로 별도 생성합니다. `pnpm run prepare:crm-local-evidence-bundle -- --out-dir=<dir>`는 로컬 report가 없으면 `verify:crm-local`을 실행한 뒤 migration evidence bundle 생성과 bundle verifier까지 이어 실행하고, 선택적으로 `--accounting-payment-report-path=<report.json>`, `--crm-ai-rag-report-path=<report.json>`, `--protected-source-reflection-report-path=<report.json>`로 제공된 passed 확장 report를 bundle slot에 적용합니다. 남은 확장 evidence report가 draft뿐이면 wrapper report에 `local-ready-pending-external`을 기록합니다. `pnpm run verify:crm-migration-evidence-bundle -- --bundle-dir=<dir>`는 bundle 파일 상태 검증이며, 기본 데모 이식 완료 감사를 대체하지 않습니다.
- CRM completion report verifier와 `verify:crm-migration-completion`의 확장 readiness 검사는 synthetic/self-test evidence marker를 기본 거부합니다. verifier self-test가 만든 통과용 JSON이나 fixture id/report는 스키마 회귀 검증용일 뿐이며, provider 운영 실행·provider-backed indexing·보호자료 반영 완료 증거가 아닙니다.
- CRM AI/RAG는 `verify:crm-ai-rag-runtime`, `verify:crm-ai-rag-runtime:unavailable`, `verify:crm-ai-rag-runtime:ready-precheck`, `verify:crm-ai-rag-runtime:ready`, `verify:crm-ai-rag-runtime-report` 실행 진입점을 제공합니다. live verifier는 opportunity/customer/activity API 선택, controlled backfill, common AI object/chunk/ACL/index state/retrieval audit를 report로 남기고, report verifier는 기존 JSON evidence가 provider-ready completion 증거인지 검증합니다. `activity`도 공용 retrieval entity filter로 정식 등록합니다. SSOO 공통 AI/RAG provider가 실제 embedding provider와 연결된 환경의 RAG 품질 검증은 확장 readiness이며, 기본 CRM 데모 이식 완료의 blocker가 아닙니다.
- 사용자가 제공한 외부 데모 소스와 DB 스키마, 영업관리 소개 자료를 분석해 1차 PRD와 백로그를 만들었습니다.
- PMS 병렬 기준선과 맞춰 CRM은 계약/청구/매출/원가의 원장성 편집을 맡고, PMS는 실행 수행과 명시 반영된 인계 스냅샷만 소비하는 경계로 고정했습니다. PMS 프로젝트 상세 인수인계 탭은 CRM 계약 후보 목록과 `/api/crm/contracts/:id/pms-handoff-preview`를 조회하고, 준비 완료 preview만 기존 프로젝트의 계약/대금/인계 스냅샷으로 반영합니다. CRM에서 PMS 신규 프로젝트를 자동 생성하지 않습니다.
- DMS 경계는 견적 markdown 초안 handoff, 견적 DMS lifecycle artifact 실행/evidence 수신, 계약서 입력 패킷 preview, DMS markdown 초안 저장 요청, DMS lifecycle artifact 실행, CRM handoff snapshot 기록으로 제한했습니다. CRM 견적 상세는 `/api/crm/opportunities/:id/quote-preview`에서 DMS 견적 초안 readiness, `crm-quote-v1` active template source path, draft path hint, DMS 견적 lifecycle을 제공하고, 준비 완료 견적은 `/api/crm/opportunities/:id/quote-dms-document-draft`로 markdown 초안을 DMS 파일 서비스에 저장한 뒤 `crm.crm_quote_dms_handoff_m`에 문서/변수/lifecycle snapshot을 남깁니다. `/api/crm/opportunities/:id/quote-dms-document-lifecycle-execution`은 DMS 서비스가 만든 template-version/template-review record와 DOCX/PDF artifact evidence를 같은 active handoff lifecycle에 반영하고, `/api/crm/opportunities/:id/quote-dms-document-execution-evidence`는 외부 DMS 실행 결과도 같은 수신 계약으로 기록합니다. DMS 설정의 관리자 템플릿 목록은 `crm-quote-v1` reviewConfirmation 검토 확정 상태를 관리합니다. CRM 계약 상세는 `/api/crm/contracts/:id/dms-document-preview`를 읽어 문서 변수와 차단 사유, deterministic 초안 경로, 저장된 초안 경로, 최신 handoff id/status/savedAt, CRM markdown 초안부터 DMS 템플릿 검토/첨부 확인/Word 산출/PDF 저장/승인까지의 lifecycle checklist를 표시하고, DMS registry의 `crm-contract-v1` active 템플릿 source path를 검토 단계 evidence로 사용합니다. 준비 완료 계약은 `/api/crm/contracts/:id/dms-document-draft`로 markdown 초안을 DMS 파일 서비스에 저장한 뒤 `crm.crm_contract_dms_handoff_m`에 문서/변수/첨부/lifecycle snapshot을 남깁니다. `/api/crm/contracts/:id/dms-document-lifecycle-execution`은 DMS 서비스가 생성한 export policy record, 템플릿 버전 snapshot, 템플릿 변경 검토, 템플릿 변경 요청 원장, 첨부 확정 원장, 승인 route policy, 공용 사용자/조직 directory snapshot, 결재선 원장 동기화 기록, DOCX/PDF, 검토/첨부/승인 workflow artifact evidence를 CRM handoff에 반영하고 `/contracts`에서 governance evidence를 함께 표시합니다. DMS 설정의 `CRM 계약 결재선`은 계약 승인 route 정책과 required roles를 관리하고, `CRM 계약 산출 정책`은 markdown evidence와 Word/PDF artifact의 조직 scope별 산출 경로를 관리합니다.
- DMS 첨부 확인 lifecycle은 CRM에서 공급자 CI와 청구계획 별첨 evidence path를 표시하고, 공급자 CI 참조는 DMS working tree/storage adapter 기준으로 검증한 뒤 DMS 실행 시점에 첨부 확정 원장으로 보존합니다.
- DMS 실행 evidence 수신은 초안 handoff가 존재할 때만 허용하며, active handoff row를 교체해 이전 snapshot을 `replaced`로 남깁니다.
- 계정, 권한, 법인, 조직, 관리자 운영은 CRM 내부가 아니라 공용 Admin/공용 권한 모델로 관리하는 전제를 반영했고, `/operations` 운영 기준 Preview에서 CRM이 소유하지 않는 항목을 명시합니다.
- 보호된 발표자료 1개는 본문 추출이 되지 않아 현재 기준선에는 미반영했습니다. 사용자가 해제본 제공과 반영을 별도 승인하기 전까지 이 자료는 데모 실행 소스 코드 이식 완료 조건이 아니라 확장 검토 후보입니다.
