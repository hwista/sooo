# PMS-CRM Boundary Launch Rebaseline

> 최종 업데이트: 2026-07-13
> 범위: PMS 런칭 직전 책임 경계, 구현 수준, 즉시 실행 백로그 기준선

이 문서는 기존 PMS 구축 자료, 현재 PMS 로드맵/백로그, CRM 이식 PRD/백로그를 대조해 CRM 분리 이후 PMS가 책임져야 할 런칭 범위를 고정한다.

---

## 1. 결론

기존 PMS 구축 자료는 영업관리, 계약, 청구, 매출, 공수, 품질, 보고, 프로젝트 실행을 한 시스템에 넣은 넓은 업무 플랫폼이었다. 현재 SSOO에서는 CRM이 별도 제품으로 분리되었으므로 PMS는 기존 PMS의 전체 범위를 그대로 소유하지 않는다.

PMS 런칭 기준은 다음으로 제한한다.

1. CRM에서 확정되었거나 내부 승인된 일을 실행 프로젝트로 수령한다.
2. 실행 프로젝트의 계획, 수행, 통제, 산출물, 종료 조건, 운영 전환을 관리한다.
3. 계약/청구/매출/원가 정보는 CRM 정본을 읽기용 스냅샷으로 소비한다.
4. 영업 기회, 견적, 계약대장, 청구 계획/실적, 매출/원가/손익 원장은 PMS에서 편집하지 않는다.
5. 고객사 원장 생성/수정/비활성화는 PMS에서 수행하지 않고, PMS는 프로젝트 실행 선택에 필요한 고객사 읽기 조회만 소비한다.

## 4. 현재 구현 판정

| 항목 | 판정 |
|------|------|
| 실행 프로젝트 관리 기반 | 구현됨 |
| WBS/작업/마일스톤 기반 | 구현됨. 목표/WBS/작업/마일스톤은 데스크톱 표와 모바일 카드 목록으로 상태·연결·진척을 확인/변경할 수 있고, 등록 다이얼로그는 작은 화면에서 스크롤 가능하게 보강됨 |
| 통제 객체 기반 | 구현됨. 이슈/요구사항/리스크/변경/이벤트는 데스크톱 표와 모바일 카드 목록으로 확인·상태 변경 가능하고, 작은 화면 등록 다이얼로그가 1차 보강됨. 기존 `Issue` 행은 신규 작성 POST/웹 create 계약을 폐기한 뒤 열린 cleanup 대상 중심의 호환성 인박스로 축소하고, 완료/전환 행은 선택 이력으로 접으며, 완료 상태 행은 프로젝트 단위 일괄 숨김 액션으로 보존 아카이브 후 비활성화함. 열린 cleanup 행은 프로젝트 단위 일괄 정식 전환으로 이슈·리스크·변경요청을 생성한 뒤 `canonicalized_cleanup` 보존 아카이브 후 비활성화할 수 있음. cleanup 요약은 활성/열린/완료/숨김 보존 건수와 물리 제거 가능 여부를 서버 기준으로 표시함. 원본 테이블 물리 제거는 활성 cleanup 대상 0건 확인 이후 별도 migration |
| 산출물/종료 조건 기반 | 구현됨. 산출물은 데스크톱 표와 모바일 카드 목록으로 제출상태·연결 이벤트를 확인/변경할 수 있고, 산출물/종료조건 등록 다이얼로그는 작은 화면에서 스크롤 가능하게 보강됨. 산출물 완료 판정은 `confirmed`/`approved`/`not_required`를 인정하고 `before_submit`/`final` 호환 입력은 표준 상태로 정규화함. 현재 단계 기본 템플릿 적용, 저장된 그룹 선택 적용, append/replace 적용 정책, 현재 목록 기반 그룹 저장이 구현됐고 종료조건 그룹 항목은 산출물 필요 여부를 보존함. 전용 템플릿 관리 화면은 그룹 편집, 초안·승인·보관, 버전 증가, 이력 조회·복구를 1차 제공함. 산출물/종료조건별 프로젝트 멤버 기반 1~5단계 승인선, 지정 승인자 승인/반려, 최종 승인 시 산출물 승인 또는 종료조건 완료 반영도 1차 구현됨. 전사 결재 엔진과 DMS 파일 검토 연동은 후속 |
| 홈/종료 가능 요약 | 구현됨 |
| 인수인계/계약/대금 서버 기반 | 부분 구현 |
| 인수인계 전용 화면 | 1차 구현. 대상 담당자는 프로젝트 멤버 중에서 고르고, 배정 역할은 활성 프로젝트 멤버 역할 코드에서 선택한다 |
| 계약/대금 전용 화면 | 읽기용 스냅샷 1차 노출과 CRM 계약 후보 preview 소비 1차. 편집 화면과 PMS 프로젝트 자동 생성은 PMS 범위 제외 |
| 계약/청구의 CRM 읽기용 스냅샷 정책 | 문서화 및 화면 정리 완료 |
| 고객사 원장 편집 | PMS 고객사 CRUD 화면/API/mutation 제거. 프로젝트 실행 선택용 읽기 조회만 유지하며 공용 조직 앵커 메타데이터를 1차 투영. 요청 등록, 프로젝트 기본정보, 기준정보 관리의 고객사 선택지는 고객사 코드와 공용 조직명/코드를 공통 규칙으로 표시하고, 조직 식별자만 있을 때는 숫자 ID 대신 정보 조회 필요 상태를 표시. 프로젝트 응답과 상태별 목록/기본정보 읽기 화면도 고객명과 공용 조직 연결 상태를 읽기 전용으로 표시. 원장 편집과 full cutover 는 PMS 범위 밖 |
| 상태별 목록 고객 필터 | 요청/제안/수행/전환 목록은 숫자 고객 ID 직접 입력 대신 PMS 고객사 읽기 조회 결과를 선택한다. 고객 열과 fallback 표시는 고객명/코드/공용 조직 라벨을 우선하며 숫자 고객 ID를 사용자 표면에 직접 노출하지 않는다 |
| 프로젝트 연결 조직 | owner/customer 는 프로젝트 기준정보와 고객 공용 조직 앵커에서 자동 반영. supplier/partner 는 PMS가 조직 원장을 만들지 않고 프로젝트 문맥의 읽기 전용 공용 조직 lookup 결과를 선택해 연결 |
| 프로젝트 멤버 배정 | 멤버 역할은 PMS 코드 기준을 사용하되, 멤버 추가 대상자는 PMS가 사용자 원장을 만들지 않고 프로젝트 문맥의 활성 공용 사용자 lookup 결과를 선택해 배정. 선택 사용자의 1차 소속 조직 앵커는 멤버 배정에 전달 |
| 단계별 상세 담당자 | 요청/제안/전환 상세의 담당자는 PMS가 사용자 원장을 만들지 않고 현재 프로젝트 멤버 중에서 선택한다 |
| 인수인계 배정 역할 | 인수인계 등록의 배정 역할은 PMS `PROJECT_MEMBER_ROLE` 활성 코드에서 선택한다. 사용자가 임의 역할 코드를 입력하지 않고, 역할 코드 원장은 PMS 코드 관리 책임이다 |
| 프로젝트 간 직접 관계 | 후속/분리/병합/연결 관계는 PMS 실행 프로젝트 간 관계로 유지한다. 직접 연결 추가는 숫자 프로젝트 ID 입력이 아니라 접근 가능한 프로젝트명/번호 검색 결과에서 선택한다 |
| 실행 상세 후속 프로젝트 | `nextProjectId` 기반 successor 호환 동기화는 유지하되, 실행 상세 화면은 숫자 프로젝트 ID 직접 입력/표시가 아니라 접근 가능한 프로젝트명/번호 검색 선택을 사용한다 |
| 런칭 표시 fallback | 고객/조직/실행 자산/프로젝트 관계/담당자 화면 fallback 은 숫자 내부 ID를 직접 보여주지 않고 이름·코드 우선 또는 정보 조회 필요 상태로 표시한다. PMS AI/RAG project/task/member/status projection 본문도 고객·플랜트·시스템·담당자·조직 내부 ID 라벨을 노출하지 않는다. 저장 식별자, ACL, metadata, API 경로는 유지하되 사용자 표면의 raw ID 노출은 런칭 검증에서 차단한다 |
| 실행 자산 기준정보 반입 | CSV/TSV 템플릿은 고객사/사이트/시스템 코드 기반으로 내려받으며, 숫자 ID 컬럼은 기존 파일을 위한 호환 매핑으로만 유지한다. PMS는 고객사 원장을 만들지 않고 읽기 조회와 코드/앵커 참조만 소비한다 |
| 보고/리뷰 이벤트 요약 | 실행 이벤트, 연결 산출물/종료조건 readiness, 피드백 큐 노출, 모바일 카드 목록, launch feedback 이슈/리뷰 이벤트 등록, 수집된 launch feedback 상태 변경·해결 처리, 런칭 피드백 공유용 스냅샷 다운로드, 현재 PMS 실행 데이터 기준 PMR/PRR 준비도 화면·초안 다운로드·프로젝트 이벤트 기반 발행 원장, 주간/월간 반복 예약 생성, 만기 예약 자동 rollover, 프로젝트 멤버 승인자 지정, 결재선 정책 선택, 수신 정책 기반 PMS 공통 알림, 승인·반려 지정 승인자 제한, 작은 화면 등록 다이얼로그, 홈에서 리뷰/피드백 탭 직접 진입, 열린 launch feedback 홈 지표·운영 신호 |

| PMS core 정합화 migration | 프로젝트 멤버·조직·관계, 인수인계, 계약 읽기 스냅샷, 목표/WBS/작업, 이슈·요구사항·리스크·변경·이벤트 및 history table 은 PMS formal migration + db-init protected baseline 적용 경로로 고정. CRM 영업/계약/재무 원장은 포함하지 않음 |

| 프로젝트 실행 자산 direct anchor 표시 | 프로젝트 목록/상세/생성/수정 응답과 상태별 목록/작업 큐/기본정보 읽기 화면은 `plantId`, `systemInstanceId` 숫자 식별자 대신 plant/site와 system instance 이름·코드를 우선 표시. 실행 자산 기준정보 자체는 PMS 런칭 범위이며 CRM 원장이 아님 |
| 기존 PMS 전체 보고/품질/공수/PMO 대시보드 | 부분 구현. 작업 단위 예상/실제 공수 입력, 작업별 일일 공수 원장, 작업 actualHours 자동 합산, 프로젝트 상세 통제 요약의 공수 표시는 구현됐지만, 전체 PMO/경영 대시보드와 전사 타임시트·노무비/회계 연동은 후속 |
| PMS 런타임 데이터 검증 | 인증 후 API smoke 확장 완료 |
| PMS AI/RAG provider-ready 증빙 | provider-ready report verifier, completion runner, evidence recorder, evidence bundle 생성/검증 경로는 준비됨. 다만 실제 Azure-backed 통과 report artifact 는 아직 없으며 draft bundle/report/placeholder summary 는 완료 증빙으로 보지 않음 |

따라서 현재 PMS는 “실행 프로젝트 관리 조각”으로는 런칭 후보이나, “기존 PMS 전체 대체”로 주장하면 안 된다.

## 6. 구현 원칙

1. PMS는 실행 프로젝트 원장이다.
2. CRM은 영업/계약/재무성 원장이다.
3. PMS의 계약/청구 필드는 런칭 단계에서 호환 스냅샷이다.
4. PMS 화면에서 CRM 정본 값을 수정하게 만들지 않는다.
5. PMS 화면에서 고객사 원장을 생성/수정/비활성화하지 않는다.
6. 기존 PMS 구축 자료의 넓은 범위는 기능 후보 목록으로만 사용하고, 책임 제품이 정해지지 않은 기능은 구현 완료로 표기하지 않는다.
